# pcb-pilot 实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让 Claude Code / Codex / DSH / Qoder 等 agent 通过 MCP 驱动嘉立创 EDA 专业版（离线/本地工程模式）完成原理图、PCB、DRC 与制造输出。

**Architecture:** 单 npm 包 `pcb-pilot`（内部模块 protocol/daemon/mcp/cli）+ 独立 `extension/`（官方 SDK 构建链产 .eext）+ `skill/`。daemon 独占 WS 端口对扩展、loopback HTTP JSON-RPC 对 MCP/CLI；动作串行队列 + token 配对 + 审计 JSONL + 写动作 readback 校验。

**Tech Stack:** TypeScript 5.7+（NodeNext ESM）、Node ≥20.17、ws 8、zod 3、@modelcontextprotocol/sdk 1.x、commander 12、vitest 3、esbuild（扩展端，vendor 自官方 pro-api-sdk，Apache-2.0）。

**Spec:** `docs/superpowers/specs/2026-11-09-pcb-pilot-design.md`（同仓库，执行者两个都读）

**对 spec 的一处细化（设计者决定）：** spec 写「npm workspace 单仓多包」，实现细化为**单 npm 包 + 内部模块**——只发布 `pcb-pilot` 一个包（`npx pcb-pilot` 直接用），extension/ 独立 package.json 不发布。理由：避免发布 4 个互相依赖的包，用户体验一条命令不变。

## Global Constraints

- Node ≥ 20.17；CI 与开发机用 Node 24；Windows 优先（路径一律 `node:path` join，不硬编码盘符）。
- 所有监听只绑 `127.0.0.1`；默认 WS 端口 `49630`、RPC 端口 `49631`；env 覆盖 `PCBP_WS_PORT` / `PCBP_RPC_PORT`。
- 状态目录 `~/.pcb-pilot/`：`token`（32 字节 hex）、`audit.jsonl`、`daemon.json`（{pid, rpcPort, wsPort, version, startedAt}）、`output/`（制造文件落盘）。
- 错误码 exact：`NOT_CONNECTED | TIMEOUT | EDA_API_ERROR | INVALID_PARAMS | TOKEN_REJECTED | UNKNOWN_ACTION | READBACK_MISMATCH`。
- 不暴露任意 JS 执行；未知 action 一律 `UNKNOWN_ACTION`；token 不得进审计日志。
- 扩展 `engines.eda: ^3.2.0`；类型包 `@jlceda/pro-api-types` ^0.4.27；esbuild 输出必须 `format:'iife', platform:'browser', globalName:'edaEsbuildExportName', bundle:true, minify:false`（官方硬性要求）。
- 单 EDA 实例单工程；写动作 readback 带 projectUuid，与 daemon 缓存不符 → `READBACK_MISMATCH` 停写。
- 离线/本地工程模式：`project.create` 不传 teamUuid 云参数；doctor 检查本地客户端 `%LOCALAPPDATA%/Programs/lceda-pro`。
- Apache-2.0；嘉立创EDA/EasyEDA 商标仅用于功能描述与标题；vendor 的官方构建脚本保留来源注释。
- 根包相对 import 一律带 `.js` 后缀（NodeNext）；extension 内 import 不带后缀（esbuild bundler）。

## Review Focus

1. 用户中途切换工程/标签页 → 写动作 readback 的 projectUuid 不符必须报 `READBACK_MISMATCH` 且不继续写（Task 3 测试）。
2. 扩展断线 / daemon 重启 → 扩展心跳超时自动重连恢复，pending 动作立即失败 `NOT_CONNECTED` 而非挂死（Task 3、Task 6 测试）。
3. Gerber 等大 base64 结果（数 MB）→ WS maxPayload 64MB  roundtrip 不截断，daemon 落盘后只回路径（Task 3、Task 7 测试）。
4. 垃圾 JSON 帧 / 错误 token / 非 hello 首帧 → daemon 不崩溃、连接被拒或帧被忽略（Task 3 测试）。
5. 两个 MCP 客户端并发动作 → 队列严格串行不交错，审计顺序与执行顺序一致（Task 3 测试）。

### Task 3: daemon 桥接核心（WS bridge + 串行队列 + RPC + main）

**Files:**
- Create: `src/daemon/bridge.ts`, `src/daemon/rpc.ts`, `src/daemon/main.ts`, `test/mock-eda.ts`
- Test: `test/integration/daemon.test.ts`

**Interfaces:**
- Consumes: Task 1 协议全部；Task 2 `getPaths/loadConfig/loadOrCreateToken/AuditLogger`。
- Produces:
  - `test/mock-eda.ts`: `class MockEdaClient { constructor(url:string, token:string); connect():Promise<void>; onAction(handler:(req:ActionRequest)=>Promise<Partial<ActionResponse>>):void; sendRaw(data:string):void; close():void; readonly ack:HelloAck|undefined }`（ws 客户端，自动回 ping→pong 由对端负责；默认 handler 回 `{ok:true,result:{echo:true}}`）。
  - `bridge.ts`: `BridgeStatus {extensionConnected:boolean, extensionVersion?:string, pendingCount:number, projectUuid?:string}`；`class ExtensionBridge { constructor(opts:{port:number, token:string, audit:AuditLogger}); start():Promise<number> /*实际端口，传0取随机*/; stop():Promise<void>; getStatus():BridgeStatus; dispatch(action:string, params:Record<string,unknown>):Promise<ActionResponse> }`。
    - 行为：单扩展连接（新合法 hello 踢掉旧连接）；首帧 5s 内必须是 hello 且 token timing-safe 比对，否则 close + `TOKEN_REJECTED` ack；`dispatch` 先 `getActionDef`（UNKNOWN_ACTION）再 `params.safeParse`（INVALID_PARAMS），无扩展 → NOT_CONNECTED；Promise 链串行；每动作按 def.timeoutMs 超时 → TIMEOUT；写动作 readback 缺 projectUuid 或与缓存不符 → READBACK_MISMATCH（首个写动作建立缓存）；每个 dispatch 结果（含失败）写审计；ping → pong；20s 无帧视为死连接 terminate 并失败 pending；maxPayload 64MB；垃圾帧忽略不崩。
  - `rpc.ts`: `createRpcServer(opts:{bridge:ExtensionBridge, version:string, port:number, onShutdown:()=>void}):Promise<{server:http.Server, port:number}>`；`POST /rpc` body `{id, method:'status'|'action'|'shutdown', params?}`；`action` 的 params = `{action:string, params:object}`；`GET /health` → `{ok:true}`；只绑 127.0.0.1。
  - `main.ts`: `startDaemon(opts?:{homeDir?:string, env?:NodeJS.ProcessEnv}):Promise<{paths:DaemonPaths, config:DaemonConfig, bridge:ExtensionBridge, rpcPort:number, stop:()=>Promise<void>}>`（写 daemon.json，stop 时删除）；文件直接运行时调用 startDaemon 并挂 SIGINT/SIGTERM。
